APPENDIX · API 명세 — 공통·전역 정의

기본 요청 규칙을 정하고, 공개 API만 예외로 둡니다.

기본 경로와 사용자 식별 규칙

servers:
  - url: /api

components:
  securitySchemes:
    MockUserId:
      type: apiKey
      in: header
      name: x-user-id

security:
  - MockUserId: []

전역 security → 기본 인증 요구
개별 API의 security: [] → 공개 예외

Swagger · 요청에 사용자 ID 지정

/api + JSON
기본 경로와 요청·응답 형식

x-user-id: 1
요청 주체를 구분하는 Mock 헤더

공개 API는 인증 제외
인증 2개 · 선택지 4개 · 공개 프로필 · 초대 조회

명세의 인증 요구와 실행 시 권한 검사는 별개입니다. 현재는 사용자 ID로 요청을 구분하며, 서버 인증·전체 API 권한 검사는 보완 대상입니다.

APPENDIX · API 명세 — 공통 스키마

공통 정의를 참조하고, 화면에 필요한 응답을 조합합니다.

components의 재사용 단위

parametersTeamId · MemberId · InviteCode · ShareToken

responsesUserResponse · StringArrayResponse · ErrorResponse

schemasUser · Profile · TeamMember 등 15개

MemberDetail:
  allOf:
    - $ref: '#/components/schemas/TeamMember'
    - type: object
      properties:
        user:
          $ref: '#/components/schemas/User'
        profile:
          $ref: '#/components/schemas/Profile'

팀별 역할·목표 + 사용자 + 공통 프로필
→ 팀원 상세 화면의 하나의 응답

팀원 상세 응답과 공통 오류 구조

공통 오류 { "message": "실패 사유" }

$ref로 경로 변수·응답·스키마를 재사용합니다. JSON 성공 응답은 객체 또는 배열이며, 별도의 data/meta 래퍼는 없습니다.
