# Order Balance Web

기존 CrewAI 발주 검토 실습을 입력·수량 수정·확정·CSV 내보내기가 가능한 로컬 웹 서비스로 확장했습니다. 이번 확장은 AI 개발 도구의 도움을 받아 구현·실행 검증했습니다. 기존 노트북의 에이전트 실행 기록과 이 웹 서비스의 실행 기록은 서로 다른 버전입니다.

## 실행

Python 3.11 이상에서 이 폴더를 작업 디렉터리로 사용합니다.

```sh
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app:app --host 127.0.0.1 --port 8310
```

브라우저에서 `http://127.0.0.1:8310`을 엽니다. API 문서는 `/docs`입니다. 선택 기능인 AI 설명에는 서버 환경변수 `OPENAI_API_KEY`가 필요합니다. 키는 브라우저에 전달하지 않습니다. 발주 계산·수량 수정·확정·CSV 저장은 키 없이 동작합니다.

외부 키 없는 AI 검토는 [Local AI Runtime](../../../projects/local-ai-runtime/README.md)을 8320에서 실행한 뒤 다음처럼 연결합니다.

```sh
AI_PROVIDER=local python -m uvicorn app:app --host 127.0.0.1 --port 8310
```

대표 화면은 로컬 Qwen3 1.7B 4-bit로 실제 생성한 설명입니다. 공개 합성 데이터 한 건에서 입력 271/출력 86 tokens, 1,211ms가 기록됐고, 발주 금액·잔액·위험 상품 수량을 Python 산출값과 대조했습니다. 평균 성능이나 모델 정확도 지표가 아닙니다. OpenAI 경로는 이번 실행에서 기존 키 인증 실패로 완료 검증하지 않았습니다.

## 실제 처리 흐름

1. 기존 `../data/06_통합발주분석.csv`의 공개 합성 데이터 36개 상품을 SQLite에 초기 적재합니다.
2. 평균 판매량 × (배송 소요일 + 검토 주기 + 안전 재고일)에서 재고 포지션을 빼 필요 수량을 계산합니다.
3. 최소·최대 수량과 주문 배수를 적용한 뒤, 품절 위험·경고·재고 일수 순으로 예산을 배분합니다. 이는 위험 우선 탐욕 배분이며 전역 최적화 알고리즘은 아닙니다.
4. 사용자가 수정한 수량을 다시 검증합니다. 음수·배수 위반·예산 초과는 저장하지 않습니다.
5. 확정한 발주서는 수정할 수 없습니다. 상태와 변경 이벤트는 `state/orders.sqlite`에 남습니다. CSV 내보내기를 지원하며 실제 공급업체로 주문을 전송하지 않습니다.
6. 선택한 AI 설명은 검증된 숫자를 바꾸지 않고 확인 사항만 설명합니다. 토큰 사용량·응답 시간을 별도로 저장합니다.

## 검증

```sh
pip install httpx
python -m unittest test_app -v
```

예산 0~500,000원에서 제약 검사, 기존 후보 금액 181,560원 재현, 잘못된 수정의 원자성, 확정 상태 변경 금지, 잘못된 CSV의 기존 데이터 보존 등 7개 테스트를 실행했습니다. 실제 브라우저에서 SKU003의 수량을 24→18로 바꾸고 저장·새로고침 후 유지됨을 확인했습니다. [검증 기록](./evidence/verification.json)을 참고하세요.

## 범위

로컬 단일 사용자용 검토 도구입니다. 운영 배포용 로그인·사용자별 매장 격리는 포함하지 않습니다. 서버는 `127.0.0.1`에서 실행하며 승인·내보내기는 로컬 DB 상태를 바꿉니다. CSV는 제공된 통합 스키마를 사용합니다. 모델 설명은 발주 판단의 보조 자료이며 계산 로직과 구분합니다.
