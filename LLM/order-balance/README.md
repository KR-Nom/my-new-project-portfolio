# Order Balance — 프랜차이즈 발주 검토

판매·재고·소비기한·예산을 함께 검토해 품목별 발주 수량과 사유를 제시하는 CrewAI 학습 프로젝트입니다. Python이 수량과 금액을 계산하고 제약을 검증하며, LLM은 검증된 결과를 해석하고 설명합니다.

## 담당 범위와 두 구성

에이전트 역할과 Task 체인 구성, 프롬프트 설계·튜닝, 실행·디버깅을 다뤘습니다.

- **5개 역할 설계:** 판매 분석가 → 재고·소비기한 관리자 → 발주 초안 담당자 → 예산 관리자 → 점주 리포터. 점주 리포트까지 연결하고, 추가 Self-Consistency 호출을 사용하지 않는 설계입니다. 이 설계의 5회 호출은 목표 구성으로, 아래 20회 실측과 다른 버전입니다.
- **공개 실행판:** [order_balance.ipynb](./order_balance.ipynb)의 판매·재고·발주·예산 4-agent 순차 실행입니다. Observation 조회와 3경로 Self-Consistency 검토를 도구로 수행합니다. 아래 CSV와 수치는 이 4-agent 실행판의 기록입니다.

주요 판단 기준은 입력에 없는 수치를 만들지 않기, Python 산출값을 재계산하지 않기, 품목 키와 출력 스키마 검증, 예산과 주문 배수 유지입니다. 결과는 점주의 승인·수정 전 발주 초안입니다.

## 입력 데이터

`data/`는 매장 ST001의 합성 데이터입니다. 상품·판매·재고·발주·예산을 품목 키로 연결합니다. 실제 고객이나 매장 운영 자료가 아닙니다.

| 파일 | 용도 |
|---|---|
| `agent_판매분석가.csv` | 상품별 판매 집계 |
| `agent_판매분석가_일별상세.csv` | 일별 상세 입력과 요약 집계 대조 |
| `agent_재고관리자.csv` | 재고·소비기한 위험 판정 |
| `agent_발주담당자.csv` | 발주 후보·공급 제약 |
| `agent_예산관리자.csv` | 예산 조정 후보 |
| `데이터검증결과.csv` | 데이터 품질 검사 결과 |
| `06_통합발주분석.csv` | 단계 간 핵심 수치 교차 확인 |

## 저장된 실행 결과

분석 대상은 36개 SKU, 최종 발주 후보는 9개입니다. 예산 500,000원 중 181,560원을 사용하고 318,440원이 남았습니다. 품절 위험은 2개, 품절 경고는 1개, 폐기 위험은 5개입니다. 합성 데이터에서 관찰한 결과로 실제 매장의 비용 절감 성과를 뜻하지 않습니다.

- [최종 발주 CSV](./results/order_balance_final_order.csv)
- [요청·토큰·비용 CSV](./results/order_balance_api_token_usage.csv)
- [당시 비용 분석과 절감 시나리오](./results/order_balance_api_token_analysis.md)

사용량 CSV의 실행은 20회 요청, 일반 입력 72,339토큰, 캐시 입력 62,592토큰, 출력 7,028토큰으로 총 141,959토큰입니다. 당시 단가로 계산한 비용은 $0.01976205입니다. 입력 30%·출력 20% 감소 시 예상 비용 27.9% 절감은 가정에 따른 시나리오이며 적용 후 실측 성과가 아닙니다. 현재 가격을 의미하지 않으며 다른 노트북 실행의 토큰 수와 섞지 않았습니다.

## 실행

이 폴더에서 Python 가상환경을 만들고 `pip install -r requirements.txt`를 실행합니다. `OPENAI_API_KEY`를 환경변수 또는 로컬 `.env`로 설정한 뒤 노트북을 위에서 아래로 실행합니다. 모델의 기본값은 `openai/gpt-4o-mini`이며 `OPENAI_MODEL_NAME`으로 변경할 수 있습니다.

판매 입력 모드는 기본 `SUMMARY`이며 `DAILY_DETAIL` 모드와 계산 결과를 비교할 수 있습니다. 마지막 PDF 출력 셀은 운영체제에 맞는 한글 글꼴 경로를 확인해야 합니다. 공개본은 저장 출력을 제거했으며 이번 공개 작업에서 유료 API를 재호출하지 않았습니다. 원본 DOCX·PDF와 가상환경은 배포하지 않습니다.
